# 设计文档

一篇设计文档描述**一次变更打算怎么做**，写在执行之前，写完冻结。
执行后的实测记录写进 `launch/`，两者不一致时以 launch 为准。

## 命名

`YYYYMMDD-kebab-case-title.md`，日期是开篇日期。新增后在下表登记。

## 模板

```markdown
# <标题>

> **Status**: Draft | Accepted | Superseded by <文件> · **Date**: YYYY-MM-DD
> **Relates to**: <ADR、需求文档>

## 1. 问题
要解决什么，为什么现在做。

## 2. 方案
怎么做，取舍是什么。

## 3. 被否决的方案
每个一句理由。

## 4. 约束与假设
数据、环境、依赖；哪些假设还没验证。

## 5. 判据
打算拿什么证明这次变更成功：可重跑的命令、要看的数字和阈值。
阈值在看到结果之前写下。
```
