# ADR 0008：MVP 接入四个外部来源的小表，在数据准备阶段合并

> **Status**: Accepted · **Date**: 2026-11-27

决策：MVP 的主表仍是 91 路往 `St. Norbert` 的准点记录（[ADR 0007](0007-mvp-one-route-direction.md)）。
另外接入三张按日期或站点索引的小表，在 CRISP-DM 的数据准备阶段（整合数据）合并进建模表：

| 文件 | 来源 | 粒度 | 内容 |
|---|---|---|---|
| `data/mvp/weather_daily.csv` | Open-Meteo 历史 archive API，取 91 路站点中部一点 | 日 | 最高、最低气温，降水，降雨，降雪，最大风速，WMO 天气代码及其文字标签 |
| `data/mvp/calendar_daily.csv` | 法定假日表（同 `probe/weather_days.py`），门户 `mfzv-893p` 停车禁令 | 日 | 是否假日、假日前一天、假日后一天、主干道除雪禁令、居民区禁令 |
| `data/mvp/stop_ridership.csv` | 门户 `bv6q-du26` 分站点上下车人数 | 站点 × 时段 × 时刻表季度 | 工作日平均上车、下车人数 |

四个外部来源是天气、法定假日、停车禁令、客流，存成三个文件。三个文件合计不到 70 KB，加上主表约 7.7 MB，仍在 20 MB 以内。
导出命令是 `uv run probe/export_mvp_extras.py`，测量结果见 [data-sources.md](../requirements/data-sources.md) §4。

## 1. 背景

ADR 0005 不接外部数据，理由是两块成本：天气的降雪量各来源对不上，恶劣天气日太少，检验不了“恶劣天气日更好”；
其余外部表要和全网线路、各期时刻表逐一对齐。ADR 0007 把 MVP 收缩到一条线路、一个方向之后，对齐的成本几乎没有了：

- 天气和日历按日期合并，一条线只要一个坐标点。
- 客流按（站点，时段，时刻表季度）合并，91 路这 16 个站在 2025-07 以来的五个季度里全都有。
- 停车禁令 2025-07 以来只有 3 条，直接展开成逐日标记。

MVP 的目标改为练出并评估模型之后，多几类特征（数值、是否值、文本标签、时间区间）也让数据准备更完整。

## 2. 决策依据

- **只接查得实、成本低的**：2026-11-27 逐个核对了 data-sources §4 的候选，四个来源能在一次请求内取全，且历史覆盖整个 MVP 时段。
- **合并放在数据准备阶段**：各表按原样存放，不预先拼进主表。数据准备阶段写明每张表的合并键和缺失处理，
  合并本身是一个能检查的步骤（行数不变、没有新增空值或者空值有解释）。
- **原来的检验不恢复**：G4 的结论不变（恶劣天气日 11 天，不够检验）。天气在 MVP 里只是特征，
  不做“恶劣天气日明显好于基线”这类事先登记的检验。

## 3. 被否决的方案

- **施工和车道封闭 `h367-iifg`**：门户只保留当前和最近的记录（`Expired` 共 74 条，最早 2024-10），
  2025-07 以来的历史对不全。91 路沿线范围内只找到 3 条。
- **中小学上课日、大学学期**：要逐个学区、学校手工查校历并核实，不是一次请求能取全的数据。
- **前一天的天气预报**（Open-Meteo historical-forecast API）：符合“前一天已知”，但要处理预报和实测的差，
  MVP 先用实测值，见 §4。
- **拼成一张宽表再导出**：省掉合并步骤，但看不出每个来源的覆盖和缺失。

## 4. 后果

- **特征准入**（[ADR 0003](0003-features-known-the-day-before.md)）：当天的实测天气在预测时点还不知道。
  MVP 用前一天的实测值做特征；用当天值的结果只能作为上限单独报告，不当作模型的成绩。
- **客流缺最近一季**：门户数据到 Summer 2026（截至 2026-09-05），2026-09-06 以后没有。
  沿用上一季的值，并标记“沿用”，算在数据准备的完整性处理里。
- **客流的时段边界门户没有公布**：早、午间、晚高峰、晚上各自的起止时间要自己设定，作为假设写明。
- **降雪量可能偏少**：data-sources §4 记下了 Open-Meteo 和 ECCC 积雪深度对不上的问题，特征照用，报告里写成局限。
- **ADR 0005 的“不接外部数据”**只对 MVP 这四个来源放开。班次重建（GTFS）、施工、校历、实时数据仍在 v2，待定。
