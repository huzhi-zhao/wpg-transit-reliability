# ADR 0002：产品回答“这一班多靠得住”，不做实时到站

> **Status**: Accepted · **Date**: 2026-11-24

决策：产品的输出是**某个尚未发车的班次**的准点概率和误车概率，预测时点是前一天。
不做车辆实时位置、到站倒计时和线路查询。

## 1. 背景

Winnipeg Transit 官方 app 和第三方 app 已经提供实时到站时间。如果本项目也做
“下一班几分钟后到”，就和现有产品直接重叠。

## 2. 决策

两类产品回答的是不同问题：

- 实时 app：车现在在哪、几分钟后到。当前状态，单个点估计，时效以分钟计。
- 本项目：明天这一班有多大把握准时，提早一班能换来多少把握。提前一天，
  输出概率分布，用于规划。

本项目的价值在研究和规划一侧：从历史记录和次日可知的条件里，学出某个班次的
可靠度。这类按班次、结合次日天气给出准点概率的工具，在主流 app 里尚未见到
（未做系统的竞品调研，v1 设计时补）。

## 3. 被否决的方案

- **做实时到站预测**：与现有产品重叠，且需要实时数据接入（API key 可用性未验证）。
  实时信息只作为 v2 修正下游预测的输入，不作为产品本身。
- **只做线路、站点层面的准点率看板**：分析价值有，但使用者得自己把看板翻译成
  “我该坐哪一班”。保留为 P0 不通过时的退路。

## 4. 后果

- 特征只能用前一天已知的信息，见 [ADR 0003](0003-features-known-the-day-before.md)。
- 评估看概率是否校准，而不是到站时间的误差。
- 应用的核心交互是“输入一次出行，比较几个班次”，而不是地图和倒计时。
