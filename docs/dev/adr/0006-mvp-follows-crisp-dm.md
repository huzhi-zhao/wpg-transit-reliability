# ADR 0006：MVP 按 CRISP-DM 六个阶段组织

> **Status**: Accepted · **Date**: 2026-11-27
>
> 🔴 2026-11-27 更正：同日的 [ADR 0007](0007-mvp-one-route-direction.md) 把 MVP 收缩到一条线路的一个方向，
> 交付做到评估为止。本篇 §2.1 的 D1–D9 和 §4 新增的事先登记项不再适用于 MVP：部署阶段（D6–D9）、
> 集成、收缩基线、业务成功判据的数字都移到 v2，待定。按 CRISP-DM 组织这一决策本身不变。

决策：MVP 的工作、代码和报告按 CRISP-DM（Cross-Industry Standard Process for Data Mining）
的六个阶段组织：业务理解、数据理解、数据准备、建模、评估、部署。
[roadmap.md](../roadmap.md) 的 MVP 交付物 D1–D7 按阶段归位，并补上标准里有、原清单里缺的几项。

## 1. 背景

原来的 MVP 交付清单按产物排（管道、特征、基线、模型、评分、分位数表、命令行），
回答了“交什么”，没回答“每一步在整个流程里起什么作用、有没有漏掉哪一步”。
CRISP-DM 是数据挖掘项目最通用的流程框架，读者可以拿它的阶段和任务逐项对照。

对照之后，原清单缺三类东西：

- **业务成功判据**：CRISP-DM 要求业务理解阶段分别写下业务判据和数据挖掘判据。
  [business-objectives.md](../requirements/business-objectives.md) §3 只有后者（Brier score、校准、可重跑），
  没有说“乘客拿到的概率达到什么程度才算对 BO-1、BO-2 有用”。
- **评估阶段与建模阶段混在一起**：标准里，建模阶段的“评估模型”看技术指标，
  评估阶段对照业务目标看结果、复查整个过程（有没有泄漏、有没有照事先登记的做）、决定下一步。
  原来的 D5 只覆盖前者。
- **部署阶段只有产物，没有维护计划和最终报告**：本数据集每天有增量，时刻表每隔几个月改版一次，
  改版后同一个计划离站的历史会断开（[ADR 0005](0005-mvp-on-time-records-only.md) §4）。
  这正是标准里“监控与维护计划”要回答的问题。

## 2. 决策

### 2.1 阶段与已有工作的对应

| 阶段 | MVP 里的内容 | 状态 |
|---|---|---|
| 1 业务理解 | BO-1、BO-2，预测单位，评估协议，范围（ADR 0002–0005） | 已有；补业务成功判据 |
| 2 数据理解 | P0 可行性探针：数据描述、覆盖率、缺失是否随机、质量核对 | P0 已完成，结论 Go |
| 3 数据准备 | D1 数据管道，D2 特征 | 待做 |
| 4 建模 | D3 基线，D4 基模型与集成，时间滚动切分（测试设计） | 待做 |
| 5 评估 | D5 评分与业务评估，过程复查，下一步决定 | 待做 |
| 6 部署 | D6 分位数表，D7 命令行查询，D8 维护计划，D9 最终报告 | 待做 |

P0 本身就是一次阶段 1、2 之间的往返：G2b 不通过后回到业务理解，把范围缩到 18:00 以前
（[ADR 0004](0004-mvp-trips-departing-before-1800.md)）；外部数据的代价看清之后，
再缩到只用准点数据集（ADR 0005）。这些往返照 CRISP-DM 的原意记录，不当作偏离计划。

### 2.2 归位时的两处调整

- **特征派生（D2）归数据准备**，不归建模。标准里“构造数据”（派生字段）是数据准备的任务。
- **时间滚动切分归建模阶段的测试设计**，在训练任何模型之前定下；
  评估阶段只使用这套切分，不再改动。

### 2.3 代码按阶段分模块

阶段 3–6 各对应一个顶层模块，阶段 1、2 的产物是文档和 `probe/` 下的探针脚本，不进主包。
数据目录按处理程度分层：原始下载、清洗后的建模表、模型输出。
具体目录名和命令入口在 MVP 设计文档里定。

## 3. 被否决的方案

- **保持按产物排的清单**：能交差，但业务判据、过程复查、维护计划这几项容易一直缺着没人发现。
- **TDSP、OSEMN 等其他流程**：TDSP 偏团队协作和平台；OSEMN 没有单独的业务理解和对照业务目标的评估阶段，
  而本项目的事先登记和 Go/No-Go 判定正好落在这两个阶段。
- **把 P0 重做一遍、按 CRISP-DM 的格式补写阶段 1、2 的文档**：内容已经齐全，只需要在 roadmap 里标出对应关系。

## 4. 后果

- **roadmap**：MVP 一节按六个阶段重排；D1–D7 编号不变，新增 D8 维护计划、D9 最终报告。
- **MVP 设计文档**原来要事先登记三件事（收缩基线的层级与强度、集成组合方式、“冬季改进更大”的门槛），
  现在加两件：业务成功判据的具体数字、代码与数据目录的布局。业务判据同样在看到留出集结果之前登记。
- **评估阶段的结论**有三种：进入 v2、回到数据准备或建模再迭代一轮、停在 MVP。
  怎么判在 MVP 设计文档里和业务判据一起写下。
- 本 ADR 只定流程和组织方式，不改变 ADR 0002–0005 定下的范围、口径和数据源。
