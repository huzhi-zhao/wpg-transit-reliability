# ADR 0005：MVP 只用准点数据集，不还原班次、不接外部数据

> **Status**: Accepted · **Date**: 2026-11-25
>
> 🔴 2026-11-25 更正：§1 第一条说历史各期时刻表“要从第三方归档逐期找”。同日稍后的窗口 B 已经找齐：
> Mobility Database 上 2025-07 以来各期首尾相接，逐月联结率 ≥ 99.95%，依据 [data-sources.md](../requirements/data-sources.md) §2.1。
> 这一条的成本比写的低：仍要维护第三方来源、按日期切换版本，但不再有找不到的风险。其余理由不受影响；
> 决策本身没有因此重新讨论。

决策：MVP 的训练、评估和查询只用 Transit On-Time Performance 一个数据集
（存档 `cymk-nyei` 的月度文件 + 最近一期 `gp3k-am4u`，两者字段相同）。

- **不联结 GTFS 时刻表**，不还原 `trip_id` 和站序。
- **不接天气、道路运营、施工、日历、客流等外部数据。**
- 预测单位从“一个班次在一个站”改为**一次计划离站**：某线路、某方向在某站点的一个计划离站时间，
  由（`Route Number`，`Route Destination`，`Stop Number`，`Scheduled Time` 的时分秒）确定。
  它在同一期时刻表内每个工作日重复出现，历史可以按它累积。
- 特征只从这张表派生，仍然只用预测日前一天已知的信息（[ADR 0003](0003-features-known-the-day-before.md)）。

## 1. 背景

原定的 MVP 有三块数据工程：回填存档、联结时刻表还原班次、拼外部因素宽表。后两块的成本在 P0 里已经看清：

- 还原班次要对齐每一期时刻表。官方只提供当前一期，历史各期要从第三方归档逐期找，
  见 [data-sources.md](../requirements/data-sources.md) §2.1。
- 外部因素里最重要的天气，降雪量在不同来源之间对不上；恶劣天气日只有 11 天，
  G4 不通过，“恶劣天气日明显好于基线”这个假设本来就检验不了，见 data-sources §4。

同时，P0 窗口 A 的方差分解显示信号主要在“哪一班”（31%），“哪一天”只占约 1%
（data-sources §5）。外部因素是在班次差别之上的修正，不是主要信号。

## 2. 决策依据

- **用户问的问题不需要班次编号也能回答。** 乘客说的“D19 在 A 站 7:46 那班”，
  用线路、站点、计划时间就能在表里唯一确定。下车站 B 的计划时间由乘客从时刻表查到后一起输入。
  丢掉的是“自动把 A、B 两站串成同一班”和“站序”这个特征，问题本身还在。
- **工作量集中到建模和评估上。** 剩下的数据工程是下载、清洗、派生特征，一张表就能完成。
- **日历不必另接。** 法定假日按周日班次运行，`Day Type` 会标成 `Sunday` 或 `Holiday`；
  只取 `Weekday` 就排除了假日（2026-10-12 感恩节全天 36,141 行，标 `Weekday` 的只有 22 行，见 data-sources §1.1）。
- **天气变化有部分替代。** 线路或全网最近几天的平均偏差会随天气、施工变差而变差，
  可以作为特征间接反映，只是滞后一到两天，也解释不了原因。

## 3. 被否决的方案

- **保留 GTFS 联结，只去掉外部数据**：站序是有用的特征，但要为每一期时刻表找到来源并逐期对齐，
  工作量和不确定性都集中在这一步。
- **保留天气，只去掉时刻表**：天气的增益在秋季几乎看不到，冬季可检验的天数又不够，
  投入换不来能检验的结论。
- **换一个更小、更简单的数据集**：已有的 P0 测量全部作废，而本数据集只用一张表时已经够简单。

## 4. 后果

- **业务目标**：BO-1、BO-2 保留，输入改为由乘客给出上车站和下车站各自的计划时间，
  见 [business-objectives.md](../requirements/business-objectives.md) §1。BO-3 仍属 v2，不受影响。
- **范围边界**：[ADR 0004](0004-mvp-trips-departing-before-1800.md) 的“首站 18:00 前发车”需要知道班次的首站，
  MVP 里拿不到，改为**本站计划离站时间早于 18:00**。两者的差别只在 17–18 时发车、18 时以后才到的下游站点。
- **评估**：取消按恶劣天气日分层，改为按时段、线路、月份分层；留出集仍包含 2025-26 冬季。
- **时刻表改版**：计划时间改版后会移动，同一个计划离站的历史会断开。
  历史统计需要退到更粗的单元（线路、站点、小时），基线的收缩正好处理这一点。
- **P0**：G3（历史 GTFS）和外部因素的可得性不再是 MVP 的前提，只影响 v2。
  缺失是否与天气、时段有关（G1、G2）仍然影响 MVP 的样本是否有偏，P0 结论照旧按探针的判定规则给出。
- **移到 MVP 之后**：班次重建、站序特征、外部因素宽表。BO-3 的换乘部分本来就要 GTFS，届时一并接入。
