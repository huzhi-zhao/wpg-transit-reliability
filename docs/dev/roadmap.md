# 路线

阶段按“要证明什么”划分，不是任务清单。每个阶段的判据满足之前，不进入下一阶段。

## P0 可行性

**要证明**：准点存档能撑起“单个班次的准点概率”这个目标。

- 缺班不是系统性偏差：抽多天、多条线路，量出每天实际出现的班次占时刻表班次的比例，
  并判断缺失是否与线路、时段、车辆有关。当前只有一天一条线的读数，
  见 [data-sources.md](requirements/data-sources.md) §3。
- 历史时刻表可得：2025-07 线网改造之后各期 GTFS 能拿到，存档记录能逐期对上班次。
- 外部因素可得：[data-sources.md](requirements/data-sources.md) §4 里标为 v1 候选的
  因素，逐个确认历史覆盖和次日可得性。

**不通过的出路**：缩小范围（只做覆盖率高的线路或时段），或改成线路、站点层面的
准点分布，不做单班次概率。这两种都要先写 ADR。

## v1 次日预测

**要证明**：在留出的时间段上，模型给出的概率是校准的，并且在恶劣天气日明显好于
历史频率基线。判据细节见 [business-objectives.md](requirements/business-objectives.md) §3。

- 范围：少数几条线路、工作日、线网改造之后的数据。
- 交付：数据管道、训练和评估、一个能输入班次并给出两项风险和替代建议的应用。

## v2 实时修正

**要证明**：用上游站点的实时偏差修正下游预测，比 v1 的次日预测更准。

- 依赖 Winnipeg Transit 开放 API（需要申请 key，可用性尚未验证）。
- 实时路段流量等 v1 只能用历史典型值的因素，在这一阶段改用实时值。
