# 路线

阶段按“要证明什么”划分，不是任务清单。每个阶段的判据满足之前，不进入下一阶段。

## P0 可行性

**要证明**：准点存档能撑起“单个班次的准点概率”这个目标。

- 缺班不是系统性偏差：抽多天、多条线路，量出每天实际出现的班次占时刻表班次的比例，
  并判断缺失是否与线路、时段、车辆有关。当前只有一天一条线的读数，
  见 [data-sources.md](requirements/data-sources.md) §3。
- 历史时刻表可得：2025-07 线网改造之后各期 GTFS 能拿到，存档记录能逐期对上班次。
- 外部因素可得：[data-sources.md](requirements/data-sources.md) §4 里标为 MVP 候选的
  因素，逐个确认历史覆盖和次日可得性。

**不通过的出路**：缩小范围（只做覆盖率高的线路或时段），或改成线路、站点层面的
准点分布，不做单班次概率。这两种都要先写 ADR。

> MVP 改为只用准点数据集之后（[ADR 0005](adr/0005-mvp-on-time-records-only.md)），
> 上面第二、三条（历史时刻表、外部因素）只影响 v2；第一条仍决定 MVP 的样本是否有偏。

## MVP 次日预测（BO-1、BO-2）

**要证明**：只用准点数据集一张表，从原始记录到次日概率预测的整条链路能跑通、能重跑，
多个模型集成后给出的概率在留出的时间段上有一套完整、诚实的评分。

**范围**

- 只做 BO-1（迟到风险）和 BO-2（误车风险），见 [business-objectives.md](requirements/business-objectives.md) §1。
- 数据只用准点数据集：存档月度文件 + 最近一期表，2025-07 线网改造之后（[ADR 0005](adr/0005-mvp-on-time-records-only.md)）。
- 3 到 5 条线路；只做 `Day Type = Weekday`；只做本站计划离站时间早于 18:00 的记录
  （[ADR 0004](adr/0004-mvp-trips-departing-before-1800.md)，口径按 ADR 0005 修改）。
- 预测单位是一次计划离站：线路、方向、站点、计划离站时间。

**交付**

| # | 交付物 | 内容 | 验收 |
|---|---|---|---|
| D1 | 数据管道 | 下载存档和最近一期表；去重、剔除偏差绝对值超过 3,600 秒的记录、按范围过滤；输出一张建模表 | 一条命令从空目录重跑出同一张表；下载的逐月、逐日行数与门户公布的行数一致（同 P0 的核对方式） |
| D2 | 特征 | 只从建模表派生，截至预测日前一天：时间特征、历史统计、近期趋势，见 business-objectives §2 | 有一项检查证明没有任何特征用到预测日当天及以后的记录 |
| D3 | 基线 | 历史频率基线，收缩和不收缩两版 | 收缩的层级和强度在看到留出集结果之前写进 MVP 设计文档 |
| D4 | 模型 | 若干基模型加一个集成模型，组合方式在 MVP 设计文档里定 | 训练可重跑，随机种子固定 |
| D5 | 评分报告 | 集成模型、各基模型、两版基线在同一留出集上的 Brier score、可靠性曲线；按时段、线路、月份分层 | 留出集按时间滚动切分，至少包含 2025-26 冬季；所有比较全部报出 |
| D6 | 预测输出 | 每个计划离站的偏差分位数表（serving table） | BO-1、BO-2 的任意截止时间都能由这张表插值得到 |
| D7 | 查询入口 | 命令行：输入线路、上车站及其计划时间、计划到站时间、下车站及其计划时间、截止时间，输出两项概率 | 对留出集里抽出的计划离站，查询结果与 D6 表中的数一致 |

**通过门槛**是 D1–D7 齐全且可重跑。事先登记的假设（见 business-objectives §3）结果无论好坏都如实报告，
不作为通过门槛。

**不在 MVP 里**：时刻表联结与班次重建、站序特征、天气等外部数据、周末与假日、18:00 以后、
全网线路、BO-3、面向乘客的应用、实时修正。

## v2 实用化（BO-3 与应用）

**要证明**：MVP 的预测能变成乘客可用的出行建议。

- **BO-3 同线路相邻班次**（早一班、晚一班）：读 MVP 的分位数表即可，不需要新模型。先做这一半。
- **BO-3 换乘与替代线路**：先用 GTFS 做路径规划找候选；两段的晚点受同一场天气影响，
  不独立，换乘风险不能两段概率相乘，要在模型层处理。单独写设计文档。
- 面向乘客的应用：输入班次给出两项风险和替代建议。
- **班次重建与外部因素**（MVP 不做，[ADR 0005](adr/0005-mvp-on-time-records-only.md)）：联结 GTFS 还原班次、
  加站序特征，接入天气等外部数据，各自在留出集上和 MVP 模型比较增益。BO-3 换乘部分本来就要 GTFS。

## v2 之后：实时修正

**要证明**：用上游站点的实时偏差修正下游预测，比次日预测更准。

- 依赖 Winnipeg Transit 开放 API（需要申请 key，可用性尚未验证）。
- 实时路段流量等 MVP 只能用历史典型值的因素，在这一阶段改用实时值。

> 早期文档（如 [ADR 0003](adr/0003-features-known-the-day-before.md) 的标题）里的“v1”即本篇的 MVP。
