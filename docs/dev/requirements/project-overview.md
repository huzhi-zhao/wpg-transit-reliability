# 项目概述

## 项目定位

**Winnipeg Transit Reliability**：给单个公交班次算准点概率的研究型应用。

用户输入线路、上车站和那班车在上车站的计划时间、下车站和它在下车站的计划时间、截止时间，
比如“D19，A 站 7:46 那班，B 站计划 8:41，9 点前要到”。产品回答两个问题：

- 车在 B 站晚于截止时间的概率（迟到风险）；
- 用户按计划到达 A 站时，车已经提前开走的概率（误车风险）。

之后再对相邻班次、替代线路算同样两个数，让用户自己决定要不要提早一班或换乘（v2）。

MVP 的主体是一个只用准点数据集的概率模型（[ADR 0005](../adr/0005-mvp-on-time-records-only.md)）：

- 线网改造以来的站点级准点记录的下载、清洗，以及每天的增量；
- 从同一张表派生特征：时间、线路和站点、历史统计、近期趋势；
- 输出校准过的概率，而不是一个点估计。

MVP 之后再加：联结 GTFS 时刻表还原班次，天气、冬季道路运营、施工、日历等外部因素。

## 与实时到站 app 的边界

Winnipeg Transit 官方 app 和第三方 app 回答的是“车现在在哪、下一班几分钟后到”：
当前状态、短时点估计。

本项目回答的是“明天这一班有多靠得住”：提前一天、对一个还没发车的班次给概率。
两者不冲突。

> 🚫 **本项目不做**：车辆实时位置、实时到站倒计时、线路查询。这些官方已经做了，
> 没有增量价值。决策见 [ADR 0002](../adr/0002-trip-reliability-not-realtime-eta.md)。

## 能预测到什么程度

晚点多半由当天的随机情况造成：突然人多、事故拥堵、车辆故障、缺司机。
这些信息前一天拿不到，运营内部的数据也不公开。所以本项目不回答“这一班明天会不会晚”，
只给概率。

P0 在窗口 A（2026 年秋季工作日）和窗口 B（2025-26 冬季工作日）把晚点的波动拆成三块，见 [data-sources.md](data-sources.md) §5：

| 来源 | 秋季 | 冬季 | 能不能学 |
|---|---|---|---|
| 哪一班 | 31% | 25% | 能。时刻表排得紧不紧、在线路上的位置、时段，都体现在历史里 |
| 哪一天 | 1% | 8% | 部分能。由天气、路况等全城一起变的因素决定；MVP 不接天气，只能靠近期趋势滞后追上 |
| 这一班在这一天 | 68% | 67% | 不能。当天的随机冲击，加上站点之间的测量噪声 |

由此得出三点：

- **产品的价值来自班次之间的差别**：
  - 各（班次，站点）的晚点率，P10 是 0%，P90 是 35%，明显比纯抽样噪声宽，
    足以支撑“坐哪一班”的比较。
  - 外部因素是在这个基础上做修正，不是主要信号。这也是 MVP 先不接外部数据的依据之一
    （[ADR 0005](../adr/0005-mvp-on-time-records-only.md)）。
  - MVP 的预测单位是计划离站，和这里的（班次，站点）基本一一对应，结论同样适用。
- **单次命中率不会高**：评估看两件事，概率是否校准，以及 resolution（预测值有没有拉开、
  方向对不对），不看命中率。见 [ADR 0002](../adr/0002-trip-reliability-not-realtime-eta.md) §4。
- **对外怎么说**：说“哪一班历来更靠得住、什么条件下会变差”，不说“预测明天几点到”。

两点保留：

- 拆分用的量是“一个班次在一天里晚点超过 300 秒的站点比例”，和要预测的单站事件不完全相同，
  只能作为量级参考。
- 冬季“哪一天”从 1% 升到 8%，仍然远小于“哪一班”。冬季月份上 MVP 的弱点会更明显，这正是 business-objectives §3 登记“近期趋势的改进冬季大于其余月份”这一假设的原因。

## MVP 范围

- 只做 BO-1（迟到风险）和 BO-2（误车风险），见 [business-objectives.md](business-objectives.md)；
- 只用准点数据集，不联结时刻表、不接外部数据，见 [ADR 0005](../adr/0005-mvp-on-time-records-only.md)；
- 交付到预测为止：数据管道、特征、基线、若干基模型加集成、评分报告、分位数表、命令行查询，
  交付清单和验收见 [roadmap.md](../roadmap.md) 的 MVP 一节；
- 3 到 5 条线路，包含 D19；
- 只做工作日，且只做本站计划离站时间早于 18:00 的记录：晚间的记录太少，
  见 [ADR 0004](../adr/0004-mvp-trips-departing-before-1800.md)；
- 只用 2025-07 线网改造之后的数据；
- 只做次日预测，不接实时数据。

范围外：BO-3 替代方案和面向乘客的应用（v2）、班次重建和外部因素（v2）、周末与节假日、
18:00 及以后、全网线路、实时修正。阶段划分见 [roadmap.md](../roadmap.md)。

## 主要风险

- **缺班**：一天里约三分之一的计划班次整班没有记录（窗口 A 全网覆盖率 62.3%；此前按 D19 一天的读数写作“约三分之二”，已被窗口 A 取代）。如果缺失不是随机的，概率会有偏。
  这决定项目能不能做，放在 P0 先查。见 [data-sources.md](data-sources.md) §3。
- **改造后的冬天少**：2025-07 线网改造到现在只有一个完整冬季，冬季的规律只有一次可学。
  MVP 不接天气，冬天变慢只能靠近期趋势特征追上，效果要在冬季月份的分层评分里看。
