# 项目概述

## 项目定位

**Winnipeg Transit Reliability**：给单个公交班次算准点概率的研究型应用。

用户输入线路、班次、上车站、下车站和截止时间，比如“D19，7:46 从 A 站上车，
9 点前到 B 站”。产品回答两个问题：

- 车在 B 站晚于截止时间的概率（迟到风险）；
- 用户按计划到达 A 站时，车已经提前开走的概率（误车风险）。

之后再对相邻班次、替代线路算同样两个数，让用户自己决定要不要提早一班或换乘（v2）。

项目主体是数据工程加一个概率模型：

- 约 6 亿行站点级准点记录的回填和增量采集；
- 在没有 trip ID 的记录上重建班次（与 GTFS 时刻表联结）；
- 天气、冬季道路运营、施工、日历等外部因素组成的宽表；
- 输出校准过的概率，而不是一个点估计。

## 与实时到站 app 的边界

Winnipeg Transit 官方 app 和第三方 app 回答的是“车现在在哪、下一班几分钟后到”：
当前状态、短时点估计。

本项目回答的是“明天这一班有多靠得住”：提前一天、对一个还没发车的班次给概率。
两者不冲突。

> 🚫 **本项目不做**：车辆实时位置、实时到站倒计时、线路查询。这些官方已经做了，
> 没有增量价值。决策见 [ADR 0002](../adr/0002-trip-reliability-not-realtime-eta.md)。

## MVP 范围

- 只做 BO-1（迟到风险）和 BO-2（误车风险），见 [business-objectives.md](business-objectives.md)；
- 交付到预测为止：数据管道、若干基模型加集成、评分报告、一个读表的查询入口；
- 3 到 5 条线路，包含 D19；
- 只做工作日，且只做首站 18:00 前发车的班次：晚间班次的记录太少，
  见 [ADR 0004](../adr/0004-mvp-trips-departing-before-1800.md)；
- 只用 2025-07 线网改造之后的数据训练线路相关部分，只需要对齐改造后的 GTFS；
- 只做次日预测，不接实时数据。

范围外：BO-3 替代方案和面向乘客的应用（v2）、周末与节假日、18:00 及以后发车的班次、全网线路、实时修正。
阶段划分见 [roadmap.md](../roadmap.md)。

## 主要风险

- **缺班**：一天里约三分之二的班次整班没有记录。如果缺失不是随机的，概率会有偏。
  这决定项目能不能做，放在 P0 先查。见 [data-sources.md](data-sources.md) §3。
- **改造后的冬天少**：2025-07 线网改造到现在只有一个完整冬季。天气效应打算用
  2017 年以来的全部数据在站点、路段层面学，线路身份只用改造后的数据。
  这个拆分是否成立，在 P0 和 MVP 里验证。
