# 业务目标

> 数据依据见 [data-sources.md](data-sources.md)。本篇写“要算什么、怎么判对错”，
> 那篇写“数据里有什么、量出来是多少”；本篇只引用结论，不复制数字的来龙去脉。

## 0. 场景

温尼伯冬季漫长，下雪、极寒、冻雨都会让公交晚点；赶上课、上班、换乘的人，
最怕的是“平时准，偏偏今天不准”。时刻表只给计划时间，实时 app 只看得到眼前这一班，
没有工具告诉乘客：**明天这一班有多大把握准时，提早一班能换来多少把握**。

## 1. 业务目标

术语：

- **班次**：时刻表里的一次发车，对应 GTFS 的一个 `trip_id`。MVP 不还原班次。
- **计划离站**：某线路、某方向在某站点的一个计划离站时间，由（`Route Number`，`Route Destination`，
  `Stop Number`，`Scheduled Time` 的时分秒）确定，同一期时刻表内每个工作日重复出现。
  MVP 的预测单位，见 [ADR 0005](../adr/0005-mvp-on-time-records-only.md)。
- **偏差**：存档里的 `Deviation`，单位秒，**负数是晚点，正数是提前**。
  它记录的是车**离站**相对计划的偏差，本项目把它当作到站时间的近似。

### BO-1 迟到风险

给定明天某线路在下车站 B 的一次计划离站（计划时间 S_B）和截止时间 D，
估计 P(实际离站时间 > D)，其中实际离站时间 = S_B − 偏差。

**MVP 的表述**（[ADR 0007](../adr/0007-mvp-one-route-direction.md)）：对数据集里的一次计划离站，
估计 P(偏差 < −a)，即晚点超过 a 秒的概率，a 在 MVP 设计文档里定。按乘客给出的 S_B 和 D 换算任意截止时间移到 v2，待定。

### BO-2 误车风险

给定明天某线路在上车站 A 的一次计划离站（计划时间 S_A）和乘客计划到站时间 T，
估计 P(实际离站时间 < T)。

实测里提前离站并不少见（D19 抽样一天，提前超过 60 秒的约 12%），
这一项对乘客的意义不小于迟到风险。

**MVP 的表述**：对数据集里的一次计划离站，估计 P(偏差 > b)，即提前超过 b 秒的概率，
b 在 MVP 设计文档里定。按乘客到站时间 T 换算移到 v2，待定。

### BO-3 替代方案对比（v2）

对同一出行，列出替代方案的 BO-1、BO-2，给出“坐早一班，准点概率从 x 升到 y”这类建议。
MVP 只做 BO-1、BO-2 的固定阈值版本，BO-3 放在 v2（[roadmap.md](../roadmap.md)）。BO-3 分两半，难度不同：

- **同线路相邻班次**（早一班、晚一班）：只是对相邻的几个班次多查几次 BO-1、BO-2，
  在应用层组合即可，不需要新模型。前提是 v2 的分位数表。
- **换乘和替代线路**：不只是组合。先要用 GTFS 做路径规划找出候选方案；
  换乘风险也不能用两段的概率相乘，因为同一场雪会让两段一起晚点，两段不独立，
  需要在模型层处理。这一半单独写设计文档。

## 2. 预测层

MVP 的范围见 [ADR 0007](../adr/0007-mvp-one-route-direction.md)：91 路往 `St. Norbert` 方向，
工作日、本站计划离站时间早于 18:00，2025-07 以后，约 8 万行。

- **粒度**：一行 = 一个工作日的一次计划离站（服务日期 + 站点 + 计划离站时间）。
- **一个模型**覆盖这个方向的全部站点，站点是特征。
- **特征**：从主表派生，加上四个外部来源的小表，分四类：
  - 时间：计划离站的小时和分钟、是否早晚高峰、星期几、月份；
  - 站点：站点编号、站点坐标；
  - 历史：同一计划离站、同一站点 × 小时，截至前一天的晚点率、提前率、偏差分位数和观测天数；
    本方向最近 3 天和 7 天的平均偏差与晚点率。
  - 外部（[ADR 0008](../adr/0008-mvp-small-side-tables.md)）：前一天的气温、降水、降雪、风速和天气标签；
    是否假日前后一天；除雪和居民区停车禁令；该站点该时段的平均上下车人数。
- **目标**：两个固定阈值的二分类（§1 的 a、b）。
- **特征准入**：只能用预测时点（前一天晚上）已知的信息，
  见 [ADR 0003](../adr/0003-features-known-the-day-before.md)。
- **模型**：至少一个线性模型（如逻辑回归，需要标准化）和一个树模型（如梯度提升树）。

**移到 v2，待定**：多线路与“线路”“全网近期趋势”特征；分位数回归和任意截止时间；
若干基模型加集成；按计划离站预先算好的分位数表（serving table）。

## 3. 评估协议

- **主指标**：Brier score；校准用可靠性曲线（模型说 80%，实际也要接近 80%）。
- **基线**：同一站点、同一计划离站截至前一天的历史频率，不收缩。
- **切分**：按时间切分，不随机切分；具体切点在训练任何模型之前写进 MVP 设计文档。
- **比较对象**：各模型和基线，在同一留出段上用同一套指标。
- **分层报告**：按时段（6 时前、6–9、9–15、15–18 时）、站点、月份分别报告。
- **MVP 的通过门槛**：抽取、准备、训练、评分可重跑，上面的比较全部报出。不要求赢过基线。

**移到 v2，待定**：

- 收缩基线（经验贝叶斯）：多线路、时刻表改版让计划离站的历史断开时才需要；MVP 这条线时刻表没改过。
- 业务成功判据：乘客拿到的概率达到什么程度才算有用（[ADR 0006](../adr/0006-mvp-follows-crisp-dm.md)）。
- 事先登记的假设：集成模型整体校准不差于收缩基线；近期趋势的改进冬季大于其余月份。
  MVP 这条线冬季晚点比例和其余月份几乎相同，见 ADR 0007 §4。

## 4. 已知约束

- **整天缺失**：91 路在 338 个工作日里只有 268 天有记录，2026-10-01 至 10-09 是空档，
  见 [data-sources.md](data-sources.md) §1.4。历史特征要按“上一个有记录的日子”算，缺的那天不补目标值。
- **结论只代表一条线**：线路按数据质量挑选，结果不能推广到全网。
- **偏差是离站不是到站**：终点站和长时间停站的站点，离站偏差与乘客关心的到站时间
  可能差得多。
- **没有载客量、车辆、司机等内部信息**：取消班次、车辆故障、缺司机都不公开，
  模型解释不了这部分晚点，报告里写成局限。
- **天气是实测值，不是预报**：只用前一天的实测天气，当天的天气变化只能靠近期趋势滞后反映；
  用当天实测值的结果只能作为上限单独报告。施工封路没有历史，接不进来。
- **客流是季度平均，且缺最近一季**：2026-09-06 以后沿用上一季的值；时段边界是自己设定的假设。
