# 业务目标

> 数据依据见 [data-sources.md](data-sources.md)。本篇写“要算什么、怎么判对错”，
> 那篇写“数据里有什么、量出来是多少”；本篇只引用结论，不复制数字的来龙去脉。

## 0. 场景

温尼伯冬季漫长，下雪、极寒、冻雨都会让公交晚点；赶上课、上班、换乘的人，
最怕的是“平时准，偏偏今天不准”。时刻表只给计划时间，实时 app 只看得到眼前这一班，
没有工具告诉乘客：**明天这一班有多大把握准时，提早一班能换来多少把握**。

## 1. 业务目标

术语：

- **班次**：时刻表里的一次发车，对应 GTFS 的一个 `trip_id`。MVP 不还原班次。
- **计划离站**：某线路、某方向在某站点的一个计划离站时间，由（`Route Number`，`Route Destination`，
  `Stop Number`，`Scheduled Time` 的时分秒）确定，同一期时刻表内每个工作日重复出现。
  MVP 的预测单位，见 [ADR 0005](../adr/0005-mvp-on-time-records-only.md)。
- **偏差**：存档里的 `Deviation`，单位秒，**负数是晚点，正数是提前**。
  它记录的是车**离站**相对计划的偏差，本项目把它当作到站时间的近似。

### BO-1 迟到风险

给定明天某线路在下车站 B 的一次计划离站（计划时间 S_B）和截止时间 D，
估计 P(实际离站时间 > D)，其中实际离站时间 = S_B − 偏差。

MVP 里 S_B 由乘客从时刻表查到后输入：不还原班次，系统不知道上车站那一班到 B 站是几点。

### BO-2 误车风险

给定明天某线路在上车站 A 的一次计划离站（计划时间 S_A）和乘客计划到站时间 T，
估计 P(实际离站时间 < T)。

实测里提前离站并不少见（D19 抽样一天，提前超过 60 秒的约 12%），
这一项对乘客的意义不小于迟到风险。

### BO-3 替代方案对比（v2）

对同一出行，列出替代方案的 BO-1、BO-2，给出“坐早一班，准点概率从 x 升到 y”这类建议。
MVP 只做 BO-1、BO-2，BO-3 放在 v2（[roadmap.md](../roadmap.md)）。BO-3 分两半，难度不同：

- **同线路相邻班次**（早一班、晚一班）：只是对相邻的几个班次多查几次 BO-1、BO-2，
  在应用层组合即可，不需要新模型。前提是 §2 的分位数表。
- **换乘和替代线路**：不只是组合。先要用 GTFS 做路径规划找出候选方案；
  换乘风险也不能用两段的概率相乘，因为同一场雪会让两段一起晚点，两段不独立，
  需要在模型层处理。这一半单独写设计文档。

## 2. 预测层

- **粒度**：一行 = 一个服务日的一次计划离站（服务日期 + 线路 + 方向 + 站点 + 计划离站时间）。
- **一个全局模型**，不按线路或站点分模型；站点多只意味着训练行多。
- **特征**：MVP 只从准点数据集派生（[ADR 0005](../adr/0005-mvp-on-time-records-only.md)），分四类：
  - 时间：计划离站的小时和分钟、是否早晚高峰、星期几、月份；
  - 身份：线路、方向、站点、站点坐标；
  - 历史统计：同一计划离站，以及更粗的线路 × 站点 × 小时、线路 × 小时，截至前一天的晚点率、
    提前率、偏差分位数和观测天数；
  - 近期趋势：同一线路、全网最近 3 天和 7 天的平均偏差与晚点率。天气、施工让车整体变慢时，
    这一项会跟着变，但滞后一到两天。
  站序、全程比例要还原班次才有，MVP 没有。
- **目标**：偏差的分布。两种做法待选：
  - 对多个分位数做回归（如 LightGBM 分位数损失），再换算成任意阈值的概率；
  - 对固定阈值直接做分类。
  前者一次训练就能回答任意截止时间，倾向前者，选定后写 ADR。
- **特征准入**：只能用预测时点（前一天晚上）已知的信息，
  见 [ADR 0003](../adr/0003-features-known-the-day-before.md)。
- **模型组合**：MVP 训练若干基模型，再做一个集成模型（如对各模型的分位数加权平均或
  stacking），具体组合在 MVP 设计文档里定。集成模型、各基模型都按 §3 的协议评分。
- **输出形式**：预测结果按计划离站预先算好偏差的一组分位数，存成一张表
  （serving table）。BO-1、BO-2 对任意截止时间的概率都由这组分位数插值得到；
  v2 的 BO-3 同线路部分只是多读几行。这一点约束了目标的做法，倾向分位数回归也是因为它。
- **训练数据**：只用 2025-07 线网改造之后的数据。改造前的线路编号和站点安排对不上，
  原计划用它学天气效应，MVP 不接天气，也就不用。

## 3. 评估协议

- **主指标**：Brier score；校准用可靠性曲线（模型说 80%，实际也要接近 80%）。
- **基线**：同一线路、站点、时段、星期类型的历史准点频率。
  - **MVP 设计待定：收缩基线。** 默认对历史频率做收缩，也就是经验贝叶斯，精算里叫可信度方法：
    观测天数少的单元往上一层（如线路、时段）的均值靠。
  - **原因**：P0 窗口 A 里，每个（班次，站点）单元多半只有十几天的观测，原始频率的离散
    被抽样噪声放大，见 [data-sources.md](data-sources.md) §5。MVP 的单元是计划离站，
    和（班次，站点）基本一一对应；时刻表改版后计划时间会移动，同一单元的历史会断开，更需要往上一层靠。
  - **要在 MVP 设计文档里定的**：收缩的层级和强度，在看到留出集结果之前定下。
  - 不收缩的原始频率作为对照一并报告。P0 的 I2 用的是原始频率，已事先登记，不改。
- **切分**：按时间滚动起点，不随机切分。留出集至少包含 2025-26 冬季。
- **比较对象**：集成模型、每个基模型、基线，在同一留出集上用同一套指标。
- **分层报告**：按时段（6 时前、6–9、9–15、15–18 时）、线路、月份分别报告。
  MVP 没有天气数据，不再按恶劣天气日分层（[ADR 0005](../adr/0005-mvp-on-time-records-only.md)）。
- **MVP 的通过门槛**：管道、训练、评分可重跑，上面的比较全部报出。MVP 的目标是能预测、
  评得清楚，不要求一定赢过基线。
- **事先登记的假设**：
  - 集成模型整体校准不差于收缩基线；
  - 近期趋势特征带来的改进，冬季月份（12 月至 3 月）大于其余月份。
  “改进”用 Brier score 的差衡量，“大于”的具体数字在 MVP 设计文档里、看到结果之前登记；
  结果成立与否都如实报告。

## 4. 已知约束

- **缺班**：P0 未通过之前，所有概率都不能对外展示。见 [data-sources.md](data-sources.md) §3。
- **偏差是离站不是到站**：终点站和长时间停站的站点，离站偏差与乘客关心的到站时间
  可能差得多，需要在 MVP 里量化。
- **没有载客量、车辆、司机等内部信息**：取消班次、车辆故障、缺司机都不公开，
  模型解释不了这部分晚点，报告里写成局限。
- **没有外部数据**：天气、施工带来的突然变化，MVP 只能靠近期趋势滞后一到两天才反映出来。
- **乘客要自己查下车站的计划时间**：MVP 不还原班次，BO-1 的 S_B 由乘客输入，输错了系统发现不了。
